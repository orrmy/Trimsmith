# Editing and implementation notes

A native macOS video cutter built with SwiftUI, AVKit/AVFoundation, FFmpeg, and ffprobe. It prepares a local working copy, derives selections from IN/OUT markers, and exports one joined video.

## Run

The built app is `build/Trimsmith.app`. Double-click it in Finder. Requires macOS 14 or later and FFmpeg/ffprobe installed in `/opt/homebrew/bin` or `/usr/local/bin`.

To rebuild, from this directory:

```sh
./scripts/build.sh
```

Uses Xcode's Swift compiler, no downloaded Swift packages. The script builds for the current Mac's architecture and applies an ad hoc code signature. This is a development build, not a notarized distribution. Development builds discover local FFmpeg; self-contained releases bundle pinned tools in `Contents/Resources/bin`. See [release instructions](RELEASING.md).

## App icon

The selected craftsman portrait is preserved in `Branding/IconConcepts/trimsmith-craftsman-v1.png`. `scripts/build-icon.sh` creates all standard macOS icon sizes in `Resources/AppIcon.icns`; the app build runs this automatically. The internal bundle identifier and temporary-directory prefixes retain the original FrameCut name for continuity.

## Editing

1. Open a video with Command-O, drop it onto the window or Dock icon, or use Finder’s Open With. Inputs such as MP4, MOV, MKV, TS/MTS/M2TS, AVI, and WebM are inspected with ffprobe; the actual contents determine compatibility.
2. Every import creates a separate local MOV working copy, including already-compatible MP4/MOV files. Review and approve any video/audio conversion or omitted tracks/chapters first. Then wait for copy/conversion and keyframe indexing to finish. Import review and progress appear in a modal sheet with the previous video hidden. Both phases show progress where duration is available, and playback, seeking, marking, and export stay disabled until ready. Cancel or Command-Q stops preparation. A failed or declined replacement import preserves the previous edit.
3. Space plays/pauses. Left/right arrows step one frame when the player supports it. Shift-left/right jump between indexed keyframes. Command-left/right select the previous/next cut point, including unused and coincident points, and seek to it. Navigation stops at either end rather than wrapping; after scrubbing it starts from the playhead. Click or drag the timeline to seek. The speed slider snaps to 0.25×, 0.5×, 1×, 2×, and 4×: number keys 1–5 select those rates, Up steps faster, and Down steps slower. Selecting speed while paused does not start playback; pause/resume keeps the selected speed, including native player restarts through AVPlayer’s default playback rate. Playback speed does not affect export duration.
4. I adds an IN cut point at the playhead; O adds an OUT. Selections appear immediately, without Return or a Keep button. In chronological order, the first IN opens a selection, the next OUT closes it, and an IN after that opens the next. Extra IN points inside an open selection and extra OUT points outside one remain visible as unused points. An unmatched IN selects through the end of the video. A newly opened file starts with no selections.
5. Click a cut point in the shared timeline row or the sidebar list to select it. Backspace (or the trash button) deletes the selected point, rebuilding selections automatically. Command-Z / Shift-Command-Z undo/redo point additions, deletions, and export-mode changes. Same-kind duplicates at the same timestamp select the existing point; an OUT followed by an IN at the same timestamp permits adjacent selections.
6. Click a green selection area above the seek bar or a selection in the sidebar to inspect its two boundaries without seeking or pausing playback. Click or drag any empty area of any timeline row to seek; green selection areas select, and marker clicks select/seek their cut point. IN uses a right-facing chevron and OUT a left-facing chevron.
7. Pick an export mode and press Command-E. All generated selections become one file in source order. Overlap caused by lossless keyframe expansion is still rejected at export.

Each inspected cut boundary shows the frame immediately before it and the frame at/after it, labeled **Included** or **Excluded** according to the effective exported selections. An unused point can have both sides included or both sides excluded. Clicking a selection shows both IN and OUT pairs; an unmatched selection shows its implicit file-end boundary. File endpoints show an explicit Start/End of video placeholder on the side where no frame exists. Active lossless boundaries use the surrounding keyframes and display raw → export timestamps when they differ; frame-exact boundaries use the cut timestamps. Unused points show their raw position. Variable-rate previews use decoded frames rather than subtracting an assumed frame duration. Hover to enlarge a thumbnail; clicking pins the large preview until dismissed. Selection, cut, and export-mode changes refresh previews asynchronously, coalescing rapid changes and cancelling stale requests. A small per-session image cache avoids repeated decoding; failed previews do not block export. These are source-boundary previews, not validation of the eventual encoded/remuxed output.

The timeline has green selection areas at the top, one shared IN/OUT point row, and a seek strip with keyframe ticks at the bottom. A white playhead crosses all lanes. Time displays use milliseconds; points retain their full underlying timestamp precision.

## Local working copies

Working copies live in the Mac's temporary directory under `FrameCut-Working/<unique ID>/`. Playback, seeking, keyframe indexing, and both export modes use only that copy. The original is read during inspection/preparation, retains its filename for the interface and default export name, is never modified, and is protected from being selected as the export destination. Once import completes, disconnecting its network volume does not interrupt editing or exporting.

Import uses the first video stream that is not an attached cover picture and retains every audio stream automatically in source order. Each audio track is assessed independently: compatible audio is copied and other codecs are converted to AAC after the normal conversion review. There is no track inclusion/exclusion control. Language, track labels, and disposition flags are retained where the output container supports them (MOV uses legacy language aliases such as ger for German). The review sheet identifies every retained audio track and each omitted additional video/subtitle/data/attachment track, plus omitted chapter markers. General container metadata is copied where possible; container-specific metadata preservation is not guaranteed.

When ffprobe reports interlaced video, the import review also shows an advisory warning: Apple playback may show artifacts even when VLC plays correctly; interlacing is a possible compatibility factor rather than proof of damage. The optional **Deinterlace for Apple playback** toggle is off by default. Leaving it off preserves supported video by stream copy. If codec conversion is already required, interlaced encoding is retained unless deinterlacing is selected. Selecting deinterlacing uses BWDIF to produce a progressive H.264 frame per field (typically 50/60 fps), re-encoding the video with the stated quality change. HDR deinterlacing remains unavailable. This decision affects the working copy and later exports; the original is unchanged.

The initial conservative policy copies 8-bit 4:2:0 H.264, 4:2:0 HEVC (including 10-bit), and ProRes video. AAC, ALAC, MP3, and common PCM audio are copied. Other video is offered as H.264 CRF 18 conversion; other audio is offered as AAC 192 kb/s conversion, independently of video. The sheet explicitly states that converted media changes quality. HDR can be copied when supported, but HDR video transcoding is not implemented. If Apple rejects a remuxed asset, the app offers video conversion with another explicit review rather than silently transcoding. Apple playback support and recording damage can still limit usability.

Preparation reads and rewrites the entire source, requires local free disk space, and preserves FFmpeg's default handling of initial timestamps/transport-stream discontinuities, with generation of missing timestamps where possible. All later marks refer to the resulting working-copy timeline. It does not promise to repair damaged recordings. Partial working copies are deleted on failure/cancellation; the previous successful copy is deleted when replaced, and the current copy is deleted on normal quit. After a crash, temporary storage may remain until the OS clears it. A replacement is prepared before releasing the old copy, temporarily requiring space for both.

## Export modes

**Lossless cutting mode:** Expands selections to keyframe boundaries and defaults to copying the working copy’s video and audio. If import involved transcoding, this avoids further quality loss but does not undo the import conversion. Each range expands to the surrounding keyframes; its effective boundaries appear in the segment list. Snapping that creates overlap is rejected. The save dialog has a file-format picker for QuickTime MOV and MPEG-4 MP4, and updates the filename extension to match. Lossless cutting defaults to MOV; frame-exact defaults to MP4. ProRes encoding is restricted to MOV. Both formats otherwise remain available when their codecs permit. Video packets outside the presentation range are dropped to prevent FFmpeg's B-frame decode timestamps from leaking the following GOP into the output. Segment durations are explicit during concatenation to reduce timestamp drift.

Lossless export performs a lightweight advisory check: it compares the container's frame count with packet timestamps retained from initial indexing, checks duration metadata, and decodes short windows around the start, joins, and end (two seconds on either side, merging overlaps). It does not rescan the source or decode the whole output twice. Short outputs whose check windows cover the whole video are decoded once to EOF, also allowing a decoded-frame count comparison. Seeking to a check window can additionally decode preroll from a preceding keyframe.

Frame-count mismatches, decoding problems, and unavailable inspection results produce a **Video saved — check playback** warning after the file is saved. The app explains the issue and asks the user to inspect the cuts and audio sync; Show in Finder and a persistent Check playback indicator remain available. Some open-GOP material may need Frame-exact mode or different cut boundaries. Only definite unusable results (an empty file or a confirmed missing video track), export/write failures, and explicit cancellation prevent publication. Warning results can replace an existing destination after the normal save-panel overwrite consent.

These are spot checks, not a guarantee that all frames or audio are correct. They can miss corruption elsewhere in a longer output. No encoding occurs in lossless mode. Compressed audio packet boundaries may still introduce small gaps/overlaps, and audio sync needs testing with real source files.

**Frame-exact:** Trims decoded video and every audio track at the marked timestamps, joins ranges in one filter graph, and encodes each track once. It defaults to 10-bit HEVC (`libx265`, CRF 22, medium preset, `hvc1` tag) with AAC audio (192 kb/s per track). Encoding audio once avoids adding AAC priming at every join. Variable frame timestamps are retained rather than assuming a constant frame rate. Odd dimensions are padded by a pixel as needed. HDR re-encoding remains unsupported; use lossless stream copy to preserve HDR.

The save dialog includes a **Video** codec selector. Lossless cutting offers stream copy, H.264, HEVC, and ProRes; frame-exact offers the three encoders because stream copy cannot guarantee exact boundaries. Choosing an encoder in Lossless cutting mode still uses the snapped boundaries shown in the editor. H.264 defaults to CRF 18 and HEVC to CRF 22; both use the medium preset and expose a whole-number CRF (0–51; lower means higher quality/larger files) and a codec-specific tune menu. H.264 offers default, film, animation, grain, still image, fast decode, zero latency, PSNR, and SSIM. HEVC offers default, animation, grain, fast decode, zero latency, PSNR, and SSIM. CRF values are codec-specific; they are not directly equivalent between codecs. H.264 encodes 8-bit 4:2:0, HEVC 10-bit 4:2:0, and each encodes every audio track to AAC at 192 kb/s. ProRes offers 422 Proxy, LT, standard 422 (default), and HQ profiles, with 10-bit 4:2:2 video and 24-bit PCM audio. CRF/tune controls are hidden for ProRes and stream copy. Stream copy re-encodes neither video nor audio. Settings are remembered separately for each cutting mode during the current app session after saving; cancellation leaves them unchanged. Filesystem safety, staged publication, cancellation, and per-track identities apply to every encoding choice.

Both modes export the selected video and every audio track. Stream-copy export copies all audio tracks; re-encoded exports trim and join each track independently and encode once to AAC or PCM according to the selected video codec. Subtitles, additional video tracks, chapters, and full metadata preservation are outside this version's scope. The app uses one unique editor window, so Finder/Dock file opens reuse it instead of creating duplicate windows sharing a player. Only one source file is edited at a time. Segments are held in memory; there is no project save/restore yet. Command-Z / Shift-Command-Z undo and redo cut-point additions/deletions, export-mode changes, and deliberate playhead moves (seeks, scrubbing, frame steps, keyframe/cut navigation). A drag is one undo action; ordinary playback ticks do not add history. History is retained after a cancelled/failed import and cleared when a new source successfully opens. No thumbnail strip, waveform, or timeline zoom yet.

Exports join and finalize in local temporary storage, with an animated striped progress bar for lossless preparation/joining/checking. Frame-exact encoding retains time-based progress. A separate saving phase copies the completed video to a hidden file beside the destination and reports actual bytes written; the bar stays at 99% during filesystem synchronization. This needs local space for both segments and the joined file. Neither the working copy nor the original source can be selected as the destination. A pre-existing destination is replaced only after success. Cancellation kills the active FFmpeg/ffprobe child directly, including children that ignore SIGTERM, and removes temporary export output. Closing the app cancels active work and waits for export cleanup; quitting does not wait for potentially stalled AVFoundation network metadata requests. Keyframe packets are parsed incrementally off the UI thread, with throttled progress updates and compact cached packet timestamps for export counting rather than a full packet-metadata JSON tree. Cancelled/replaced loads cannot overwrite the current loading state.

## Verification

```sh
./scripts/test.sh
```

The integration tests generate eight-second fixtures locally. They verify H.264/HEVC/ProRes HQ exact outputs and pixel formats, codec tags, audio codecs, animation tunes, CRF quality/size changes, rejection of invalid settings without replacing old files, keyframe discovery and snapping, overlap rejection, exact frame counts with and without audio, decoded frame hashes at H.264 and closed-GOP HEVC lossless boundaries, saving an open-GOP HEVC cut with a review warning, bounded inspection windows, advisory metadata/decoding failures, fatal empty/no-video outputs, preservation of an existing destination after export failure, replacement of an existing output, byte-identical measured saving and cancelled-save preservation/cleanup, and cancellation (including during verification) without a published output. Import tests additionally verify MP4/MKV/TS remux frame hashes and cut/join outputs, editing/export after the original disappears, AVI video conversion, AC3 conversion with unchanged video, track/chapter omission summaries, interlacing detection and warning, default interlaced copy hashes, optional progressive output at field rate, interlacing preservation through mandatory codec conversion, cancellation cleanup, ProRes multi-track PCM output, and byte-identical originals. Fixtures remain in `build/test-media` for manual playback testing.

Boundary-thumbnail tests compare decoded PNG images against known source frames for snapped and exact boundaries, excluded out-frames, file ends, variable frame rates, and long presentation gaps. Editor tests also cover rate selection, clamping, live changes, pause/resume, and stale thumbnail replacement.

Additional editor tests cover automatic selection generation from unordered points, unused points, adjacent/equal-time boundaries, duplicate suppression, implicit EOF, point addition/deletion/mode undo and redo, four preview slots and selection changes, previous/next cut navigation including unused/coincident points and endpoint behavior, undoable seeks/drags/frame steps/keyframe jumps, selection without seeking or pausing playback, redo branching, undo gating during import and history preservation after cancellation, local-copy isolation and cleanup, failed/declined import preservation, explicit conversion approval, transport streams (including misleading extensions), queued cold-launch and warm document-open events, disabled playback/editing while indexing, progress updates, cancellation of an actively running probe that ignores SIGTERM, prompt shutdown, and opening another file after cancellation. The app bundle registers supported document types as an alternate viewer, without making itself the default video app. Real Dock dragging and real WiFi-volume behavior still need manual retesting of this build. Earlier native UI verification covered opening a fixture, rendering the player and timeline, and frame-stepping controls. This is not yet a guarantee for all Apple-playable formats: longer recordings, variable-frame-rate files, nonzero timestamps, rotation, multiple streams, and real-world audio joins need further testing.

## Source layout

- `Sources/TrimsmithApp.swift`: app, native player view, editor interface, timeline, menus, keyboard shortcuts.
- `Sources/AppDelegate.swift`: Finder/Dock document events, queued cold-launch opens, application shutdown.
- `Sources/EditorControls.swift`: discrete playback-speed slider, small boundary images and enlarged hover/click previews.
- `Sources/BoundaryPreview.swift`: cancellable FFmpeg boundary-frame decoding.
- `Sources/ExportControls.swift`: native save-dialog codec, quality, tune, profile and container controls.
- `Sources/EditorModel.swift`: AVFoundation playback, cut points and automatic selections, file dialogs, task lifecycle.
- `Sources/ImportEngine.swift`: track inspection, import plans/review summaries, local copy ownership, remuxing and explicit conversion.
- `Sources/MediaEngine.swift`: tool discovery, cancellable processes, keyframe index, FFmpeg export, validation.
- `Tests/EngineTests.swift`: generated-media integration checks.
- `Tests/ImportTests.swift`: working-copy remux/conversion, omissions, source isolation and cancellation checks.
- `Tests/EditorTests.swift`: import review, document events, indexing gate/progress, cancellation and shutdown regression checks.

- `Tests/BoundaryPreviewTests.swift`: frame-level thumbnail comparisons for constant/variable frame rates and exclusive boundaries.
